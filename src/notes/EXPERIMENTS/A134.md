## 关键发现

### fulfill 使用 frank_wolfe 成功
- fulfill: 2500 agents, 71.2% narrow, 分数 1.120
- maze: 40 agents, 16.5% narrow, 分数 0.090
- **矛盾**: fulfill 窄通道更多但使用 frank_wolfe 成功

### 为什么 frank_wolfe 对 maze 崩溃?
可能原因:
1. **流量不稳定**: maze 结构导致 frank_wolfe 流量计算不稳定
2. **收敛问题**: 窄通道中的冲突导致优化无法收敛
3. **Agent 数量**: fulfill 2500 agents vs maze 40 agents

## 核心问题分析

### maze 分数极低的原因
- 40 agents 只有 45 tasks / 500 steps
- makespan 达到最大值 500
- 每个 agent 平均只完成 1.1 个 task

### PIBT 在 maze 上失败的原因
PIBT 是分布式算法，每个 agent 独立做决策。在窄通道中:
1. 多个 agents 同时想通过同一窄通道
2. PIBT 的 priority inheritance 不能有效解决
3. Agents 进入等待死锁状态

### SIPP 是正确方向
Team_RAPID 用 SIPP 处理窄通道:
- 追踪每个位置的 safe time intervals
- 显式调度 agents 通过窄通道
- 需要架构级别改动
