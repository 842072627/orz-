# A124: SIPP 实现 - 失败 (2026-04-23)

## 目标
提升 random 分数 (当前 0.52，目标 0.98+)

## 结论: ❌ 失败

### 尝试 1: Greedy SIPP (astar_sipp)
- **方法**: 贪婪搜索 + PathTable 冲突检测
- **结果**: ❌ 分数降至 0.27 (从 0.52)
- **原因**: 没有 A* 启发式，greedy 在开放地图上效果很差

### 尝试 2: Conflict Penalty (astar_with_conflict_penalty)  
- **方法**: 在现有 A* 上加冲突惩罚
- **结果**: ❌ 分数降至 0.497 (从 0.52)
- **原因**: PathTable 信息过时，无法正确反映未来位置

## 根本原因

我们的 A* 架构使用 MemoryPool，每个位置只存储一个状态。
Team_RAPID 的 TimeSpaceAStarPlanner 使用:
- State = (pos, orient, timestep)
- `all_states` set 来跟踪多个时间步
- ConstraintTable 进行冲突检测

这允许 Team_RAPID 正确进行时隙规划 (SIPP)。

我们的 MemoryPool 架构无法支持这个，因为每个位置只能有一个状态。
