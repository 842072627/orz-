## 目标

- **结论**: 问题在 PIBT 算法本身，不是参数或调度器

## 问题分析

### PIBT 的局限

```cpp
// 当前 PIBT 只检查当前位置是否被占用
if(occupied[next.location])
    continue;
```

这意味着：
1. Agent A 在时间 t 检查位置 P
2. 位置 P 空闲，Agent A 决定移动到 P
3. 但 Agent B 同时也决定移动到 P（时间 t+1）
4. 冲突！PIB T 的因果机制介入，但可能效率不高

### SIPP 的解决方案

SIPP 使用 Interval（时间间隔）：
- 位置 P 在时间 [5,10] 可通行
- Agent A 可以在时间 5 通过
- Agent B 必须在时间 10 之后才能通过

关键数据结构：
- **ReservationTable**: 追踪所有位置的占用时间
- **Safe Interval**: 某个位置在某个时间段可安全通行

## 实现计划

### 简化版 SIPP（仅用于窄通道）

不需要实现完整的 SIPP，只需要：

1. **识别窄通道位置**
   - 位置只有 2 个邻居（单向通行）

2. **追踪窄通道占用**
   - 简单的 interval 表

3. **在 PIBT 中考虑 interval**
   - 不只是检查当前位置，而是检查目标时间是否可通行
