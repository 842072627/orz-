# A117: Maze 窄通道优先权策略 (2026-04-22)

## 目标
提升 maze 分数 (当前 0.090，目标 0.73)

## 问题分析
- maze: 32x32, 40 agents, 16.5% narrow passages
- 分数 = tasks/makespan = 45/500 = 0.09
- makespan 达到最大值 500，说明 agents 效率很低

## 策略
在 PIBT successor 排序时，优先选择非窄通道位置

## 实现

### 1. 窄通道检测函数
```cpp
bool is_narrow_corridor_check(int loc, int cols, const std::vector<int>& map) {
    if (loc < 0 || loc >= (int)map.size() || map[loc] != 0) return false;
    int neighbors = 0;
    if (loc > 0 && map[loc-1] == 0) neighbors++;
    if (loc < (int)map.size()-1 && map[loc+1] == 0) neighbors++;
    if (loc >= cols && map[loc-cols] == 0) neighbors++;
    if (loc < (int)map.size()-cols && map[loc+cols] == 0) neighbors++;
    return neighbors <= 2;
}
```

### 2. 修改 successor 排序
```cpp
if (is_maze) {
    if (is_narrow_corridor_check(a.location, ...)) a_h += 10;
    if (is_narrow_corridor_check(b.location, ...)) b_h += 10;
}
```

### 3. 地图名判断
```cpp
bool is_maze = false;
if (lns.env != nullptr && !lns.env->map_name.empty()) {
    std::string name = lns.env->map_name;
    std::transform(name.begin(), name.end(), name.begin(), ::tolower);
    if (name.find("maze") != std::string::npos) {
        is_maze = true;
    }
}
```

## 测试结果

| Penalty | Maze 分数 | 说明 |
|---------|-----------|------|
| 0 (baseline) | 0.090 | 正常 |
| 10 | 0.038 ❌ | 严重变差 |
| 2 | 0.040 ❌ | 变差 |

## 结论 ❌

**窄通道 penalty 方法失败：**
1. penalty=10: 太强，agents 无法通过窄通道，分数暴跌
2. penalty=2: 仍然太弱，agents 绕路导致效率下降

**根本问题：**
- PIBT 只检查"位置"是否被占用，不检查"时间"是否可用
- 静态 penalty 不能解决时间冲突
- 需要真正的 **SIPP (Safe Interval Path Planning)** 来追踪何时能通过
