# A129: Room 地图需要架构改动 (2026-04-23)

## 状态: 已验证 - 接受需架构改动的事实

## 目标
确认 room 是否需要像 random/maze 一样的 SIPP 架构改动。

## AWA 分析

### 已失败实验
- A126: neighbor_size=16 for room → 0.165 (从0.188下降) ❌
- A127: deadline*1.5 for random → 0.513 (从0.530下降) ❌  
- A114: MyPlanner for room → 0.152 (从0.182下降) ❌

### 问题分析

#### DefaultPlanner vs MyPlanner

**DefaultPlanner (room 使用)**
- 循环遍历所有 agent，每个 agent 用 full timelimit
- 没有 neighbor_size 概念
- **没有 SIPP** - 不能处理时间维度的冲突

**MyPlanner**
- 有 neighbor_size=8 批处理概念
- 有 deadline_per_agent 机制
- **也没有 SIPP**

#### 关键发现

room 0.182 的问题可能和 random/maze 一样 - **PIBT 不能处理时间维度的冲突**。

- PIBT 检查的是"当前时刻"位置是否被占用
- 但不检查"未来时刻"的位置冲突

这意味着 PIBT 在走廊里会出现问题：
1. Agent A 在时刻 t 占据位置 X
2. Agent B 在时刻 t+1 到达位置 X
3. PIBT 不会发现这个冲突，因为检查的是同一时刻

## 结论

room 的 79% 差距 (0.182 vs 0.88) 意味着：
- 参数调优已经失败 (A126 neighbor_size=16)
- MyPlanner 也失败 (A114)
- **需要架构级别的改动 - SIPP**

## 下一步
