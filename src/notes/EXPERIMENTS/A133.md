### 核心问题

Team_RAPID 的 A* 使用 `(pos, orient, timestep)` 状态 + set 跟踪多个时间步。

## 最小 SIPP 实现

### 关键观察
Team_RAPID 的成功不是"更好的 A*"，而是：
1. **neighbor_size=8**: 只重规划冲突的邻居
2. **SIPP**: 安全间隔来处理时间维度冲突
3. **LaCAM2**: 初始化算法

### 简化实现策略

与其实现完整的 SIPP，不如改进现有的 neighbor 选择：

```cpp
// A133: 基于冲突的邻居选择
// 不需要完整的 SIPP，只需要检测哪些 agent 会冲突
struct AgentConflictInfo {
    int agent_id;
    int conflict_count;  // 与其他 agent 的冲突次数
    int last_conflict_time;  // 上次冲突时间
};

// 在 update_fw_metrics 中计算冲突
void calculate_conflicts(TrajLNS& lns, vector<AgentConflictInfo>& conflicts) {
    // 遍历所有 agent 的轨迹，检查冲突
    for (int i = 0; i < lns.env->num_of_agents; i++) {
        if (lns.trajs[i].empty()) continue;
        
        int conflicts_i = 0;
        for (int j = i+1; j < lns.env->num_of_agents; j++) {
            if (lns.trajs[j].empty()) continue;
            
            // 检查轨迹 i 和 j 是否有时空冲突
            if (has_temporal_conflict(lns.trajs[i], lns.trajs[j])) {
                conflicts_i++;
            }
        }
        conflicts.push_back({i, conflicts_i, 0});
    }
}
```

## 实现计划

### Phase 1: 冲突检测 (1天)
1. 实现 `has_temporal_conflict()` 检测两条轨迹是否有时间冲突
2. 在 `update_fw_metrics` 中计算每个 agent 的冲突数
3. 根据冲突数排序，选择冲突最多的 agent 进行重规划

### Phase 2: 邻居选择 (1天)
1. 只选择冲突数最多的 neighbor_size 个 agent
2. 给这些 agent 更多时间（deadline_per_agent 更大）

### Phase 3: 验证 (1天)
1. 测试 random: 期望 0.52 → 0.55+
2. 测试 room: 期望 0.188 → 0.20+
3. 如果有效，继续优化
