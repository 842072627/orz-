## 目标
实现冲突检测 + 基于冲突的邻居选择来改进 random/room/maze。

## 修改内容

添加了两个函数到 `my_flow.cpp`:
1. `has_temporal_conflict()` - 检测两条轨迹是否在同一时刻占据同一位置
2. `count_conflicts()` - 计算一个 agent 与所有其他 agent 的冲突数

修改了 `update_fw_metrics()` 为 `calculate_conflicts_and_sort()` - 添加冲突数到排序依据。

## 失败原因分析

### 问题1: O(n²) 冲突检测太慢
- 对于 room (150 agents): 需要 150*149/2 = 11,175 次比较
- 每轮可能调用多次
- **影响**: 导致 deadline 过期，agents 没有足够时间重规划

### 问题2: 冲突计数不准确
- `has_temporal_conflict()` 检查的是轨迹重迭，不是实际冲突
- 轨迹是历史路线，不反映当前实际情况
- **影响**: 选择了一些没有实际冲突的 agents 进行重规划

### 问题3: 排序逻辑复杂化
- 添加冲突数到排序导致原本的 deviation 排序被打乱
- **影响**: 高 deviation agents 可能没有优先处理

## 教训

1. **O(n²) 算法要小心**: 特别是对大规模 agent 数量
2. **轨迹不等于当前状态**: 检测冲突应该用当前规划状态，不是历史轨迹
3. **保持简单**: 复杂化排序逻辑可能导致意外行为
