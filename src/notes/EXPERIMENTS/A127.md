# A127: 冲突检测后重规划 (2026-04-23)

## 目标
提升 random 分数 (当前 ~0.53，目标 0.98+)

## 背景

### A124 失败教训
- **Greedy SIPP**: 没有 A* 启发式，效果很差
- **Conflict Penalty**: PathTable 信息过时，无效

### 核心问题
我们的 A* 不考虑时间维度。路径只是位置的序列，没有时间信息。
Team_RAPID 用 `(pos, orient, timestep)` 状态来检测时间冲突。

### 新思路: 检测后重规划
1. 运行标准 A* 获取所有路径
2. 检测哪些 agent 在未来会有冲突
3. 对冲突的 agent 重新规划（通过更大的 deadline）

## 实现计划

### Phase 1: 检测冲突的 agent
在 `update_traj` 成功后，检查是否有冲突：
- 遍历所有 agent 对
- 如果两个 agent 在相同时间位于相同位置，标记冲突

### Phase 2: 对冲突 agent 重规划
对于有冲突的 agent，给它们更多时间来重新规划。
这不是完整的 SIPP，但可能减少冲突。

### Phase 3: 测试
- random: 单独测试 3 轮
- 验证是否比 baseline (0.53) 更好

- 高风险：可能无效
- 高回报：如果成功，可能接近 Team_RAPID 的 0.98+
