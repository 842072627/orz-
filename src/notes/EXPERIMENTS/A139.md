## 关键发现

### 1. Team_RAPID NeighborGenerator 核心逻辑

**randomWalk 邻居选择**:
```cpp
int a = findMostDelayedAgent(idx);
set<int> neighbors_set;
neighbors_set.insert(a);
randomWalk(a, 0, neighbors_set, neighbor_size);
```

**findMostDelayedAgent**: 找到最大延迟的 agent，然后通过 random walk 扩展邻居。

**randomWalk**: 从一个 agent 开始，沿着它的路径随机 walk，收集冲突的 agents 直到达到 neighbor_size。

### 2. 我们的问题

**我们的 get_deviation**: 只计算当前偏差，不考虑路径冲突。

```cpp
std::pair<int,int> dists = get_source_2_path(
    lns.traj_dists[i], lns.env, 
    lns.env->curr_states[i].location, 
    &(lns.neighbors)
);
```

这只能检测"当前偏离轨迹多少"，不能检测"路径冲突"。

### 3. Team_Kitty_Knight 使用 intersection

```cpp
bool NeighborGenerator::generateNeighborByIntersection(Neighbor & neighbor) {
    // 选择一个 intersection (degree >= 3 的位置)
    // 获取在这个 intersection 附近的 agents
    path_table.get_agents(neighbors_set, neighbor_size, location);
}
```

这是另一种邻居选择策略。

## AWA 分析

### 为什么 random/bos/room 低？

可能的解释：
1. **邻居选择不够智能** - 只用 deviation，不考虑路径冲突
2. **缺少时间维度** - 没有 SIPP，无法处理时间冲突
3. **缺少 LaCAM2 初始化** - 初始路径质量不如 LaCAM2

### 解决方案

**A: 实现 conflict-based neighbor selection** (高风险/高回报)
- 用路径冲突信息选择邻居
- 估计工作量大，但潜在提升高

**B: 实现 RandomWalk neighbor selection** (中等风险/中等回报)
- 类似 Team_RAPID 的方法
- 从最大延迟 agent 开始 random walk

**C: 继续调参** (低风险/低回报)
- 已经失败多次
