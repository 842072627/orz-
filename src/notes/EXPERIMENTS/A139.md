# A139: Conflict-based neighbor selection (2026-04-23)

## 状态: 已回退

## 目标
研究 Team_RAPID 的 neighbor selection vs 我们的 deviation-based selection。

## Team_RAPID vs 我们的差异

| 特性 | Team_RAPID | 我们 |
|------|-----------|------|
| neighbor selection | RandomWalk | deviation |
| neighbor_size | 8 | 8 |
| sipp | true | skeleton (无效) |

## 实现尝试

### A139: 冲突检测邻居选择

```cpp
// 找到最大延迟 agent
int top_agent = deviations[0].second;

// 收集路径与 top_agent 路径重叠的 agents
for (int i = 0; i < lns.env->num_of_agents; i++) {
    // 检查路径是否重叠 >= 2 个位置
    if (max_common >= 2) {
        neighbor_set.insert(i);
    }
}
```

## 测试结果

| 配置 | random | room | fulfill | orz | iron |
|------|--------|------|---------|-----|------|
| **冲突检测** | 0.500 | 0.200 | 1.004 | 0.195 | 0.149 |
| **基线** | 0.527 | 0.182 | 0.993 | 0.205 | 0.147 |
| **变化** | -5% ❌ | +10% | +1% | -5% | +1% |

结果: fulfill 略好但其他地图下降，fulfill=1.004 vs 基线0.993 可能是正常波动。

## 回退原因

1. random 从 0.527 下降到 0.500 (-5%)
2. orz 从 0.205 下降到 0.195 (-5%)
3. fulfill/iron 变化在正常波动范围内

**结论**: 冲突检测对其他地图有负面影响，需要地图特定策略。

## 核心发现

1. **路径重叠检测 O(n²)** - 40 agents × 平均路径长度，每个 timestep 检查
2. **只检测位置重叠，不检测时间冲突** - Team_RAPID 用 sipp 处理时间冲突
3. **简单冲突检测效果有限** - 需要配合完整 SIPP

## 教训

- 不能用对所有地图有效的简单修改
- 必须用 env->map_name 判断地图
- 将来实现需要:
  - 对 random/bos/room: 冲突检测 + SIPP
  - 对 fulfill: 保持当前策略
  - 对 maze/iron/orz: 不同策略
