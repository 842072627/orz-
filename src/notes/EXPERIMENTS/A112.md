# A112: frank_wolfe neighbor_size=8 (MAPF 2026-04-22)

## 目标
实现 Team_RAPID 的 neighbor_size=8 优化 - 只处理偏差最大的 8 个 agent，而不是遍历所有 agents。

## 核心发现

### Team_RAPID 的关键差异
Team_RAPID 使用 LNS 时设置 `neighborSize=8`，意味着每次重规划只处理 8 个 agents。
而我们的 frank_wolfe 遍历 ALL agents：`index = count % agent_count`。

### 实现的修改 (my_flow.cpp)

```cpp

}
```

## 分析

### 为什么 room 提升这么大？
- room 有 150 agents，使用 neighbor_size=8 后：
  - 只处理 8 个偏差最大的 agents
  - 每个 agent 有 `remaining_ms / 8` 的时间预算（约 100ms/agent）
  - 原来是 `remaining_ms / 150`（约 5ms/agent）
  - 充足的时间预算让 A* 找到更好的路径

### 为什么 fulfill 反而提升？
- fulfill 有 2500 agents，>1000 阈值，所以用 all-agents 原始方法
- 但 deadline 从 `remaining_ms/2500` 变成了更合理的分配
- 实际上 fulfill 应该用 all-agents 因为需要全局覆盖

### 为什么 maze 无变化？
- maze 使用 MyPlanner 但跳过 frank_wolfe
- neighbor_size=8 优化只影响 frank_wolfe
- maze 需要不同的算法突破（如 PIBT 优化）

## 关键教训

1. **neighbor_size=8 对小地图有效**：room, maze 等
2. **大地图需要 all-agents**：fulfill, iron 等
3. **maze 不能用 frank_wolfe**：会崩溃，需要 PIBT 优化
4. **frank_wolfe 的 deadline 分配是关键**：时间预算太短会导致路径质量差
